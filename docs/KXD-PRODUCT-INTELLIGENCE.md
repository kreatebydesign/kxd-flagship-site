# KXD Product Intelligence

**Status:** P0-A architecture approved as product law · **P0-B contracts complete** · **P0-C automatic inventory complete**  
**Location:** `lib/product-intelligence/`  
**Verifiers:** `npm run verify:product-intelligence-p0b` · `npm run verify:product-intelligence-p0c`  
**Boundary:** Infrastructure for building KXD OS — not client-facing, does not change KXD OS product functionality.

## Mission

Can someone understand, evaluate, and continue building KXD OS without relying on conversation history or founder memory?

If not — the system is incomplete.

## Permanent law (P0-A — immutable)

1. Evidence before opinion  
2. One owner per truth  
3. Decisions are first-class objects  
4. Scores explain movement, never vanity  
5. Roadmap items must cite evidence + decision  
6. Chat is not memory  
7. Docs may exist, but Intelligence owns meaning  

### Core flow

```
Reality → Observers → Evidence Registry → Intelligence Domains
→ Scores / Valuation / Competitive / Friction → Decision Archive
→ Roadmap Candidates → Build Authorization → Verified Reality
```

P0-A architecture is product law. Do not redesign or simplify it.

### Object types

Every object includes: unique ID, type, title, status, owner role, created date, last reviewed, next review, evidence references, related objects, confidence, summary, structured detail, update channel, version.

Types: `doctrine`, `product_dna`, `vision`, `product_inventory`, `architecture`, `experience`, `design_system`, `evidence`, `decision`, `founder_friction`, `competitive_insight`, `roadmap_item`, `technical_debt`, `release`, `score`, `valuation`, `health_snapshot`, `hall_of_fame`, `product_kill_list`, `future_bet`.

No object may exist without an owner.

### Product DNA

Harder to change than Doctrine. Defines what KXD OS fundamentally is.

Supports: Core Beliefs · Product Principles · Founder Principles · Craft Standards · Non-Negotiables.

Never becomes roadmap. Never becomes features. Update channel: **protected**.

### Hall of Fame

Defining product moments. Each entry records why it mattered, what changed, what it teaches.

### Product Kill List

Intentional rejection archive. Idea · reason rejected · evidence · optional reconsideration date.

### Future Bets

Believed and valuable — not approved, not scheduled. Never auto-promote to roadmap. Promotion requires Decision.

### Evidence Registry

Evidence kinds include: commit, verifier, release, UX observation, founder observation, competitive review, architecture review, roadmap decision (+ code / observation / review).

Nothing references chat history.

### Relationship model

Canonical trace:

`founder_friction → decision → roadmap_item → release → valuation → hall_of_fame`

Typed allowlist in `lib/product-intelligence/relationships.ts`.

### Versioning

Every update: version · timestamp · reason · author · generated by · human approved · delta summary.

### Update Engine

Channels: **automatic** · **generated_draft** · **manual_approval** · **protected**.

Doctrine, Product DNA, and Vision cannot change automatically.

### Root index

Load entry: `PRODUCT_INTELLIGENCE_INDEX` from `lib/product-intelligence`.

Entry points defined for humans, Cursor, and future AI. No implementation UI.
